Start with the assigned [GitHub issue](https://github.com/Ewager1/applicable/issues) and the relevant edit points below. Consult the [input contract](input-format.md) or [specification](project-spec.md) only for the behavior being changed. [The project board](https://github.com/users/Ewager1/projects/6) carries current work status. The [development plan](project-plan.md) records scope and sequence; dated verification records describe their tested commits, not a fresh check of the current checkout.

The app has a strict TypeScript parser/PDF core and React/TypeScript interface retaining the HTML/CSS, built with Vite, local pdfmake and bundled Source Sans 3. No backend, account, resume storage or application analytics is involved.

`src/main.tsx` mounts the interface; `src/index.html` is only the HTML shell. `examples/` owns canonical text examples, `proof/` owns synthetic PDF/layout fixtures and frozen visual baselines, and `tests/` owns parser/filename/application/lifecycle checks. Keep developer-only proof, tests and agent-usage tools out of the production bundle. See [development boundaries](development.md#typescriptjavascript-boundary) for Node type stripping and the proof server's allowlisted TypeScript routes.

## Data flow and invariants

1. `useResumePdf.ts` takes the exact textarea source and calls the pure parser. A failed result contains ordered, human-readable errors and original one-based lines where available; a successful result contains the complete `Resume` and separate `targetCompany` filename metadata, never partial data.
2. The model stores supplied job/bullet/category order and wording. Skills `items` remains a comma-separated string. PDF generation fixes only section order; it does not sort, rewrite or deduplicate content.
3. Local fonts and the PDF engine load after validation. The renderer checks glyphs and measures heading keep-groups, then produces one byte buffer. Preview and download use the same Blob URL; native viewing has a download fallback.
4. Every asynchronous boundary checks the captured source revision and active lifecycle. Editing invalidates old output, stale pending work cannot download, failures preserve input, and repeated submissions do not queue exports. Unmount cancels delivery and revokes URLs; React StrictMode replays cleanup safely. Preserve these guards when editing the hook.

### Formatting and commit hooks

Prettier uses single quotes and a 100-character print width. Run `npm run format` to format maintained source, tests, configuration and documentation, or `npm run format:check` to check without writing. `.prettierignore` preserves generated font coverage, literal examples/fixtures, frozen baselines and third-party font/license data. Run `npm run lint:fix` for ESLint's safe automatic fixes; the React Hooks rules check hook placement and effect dependencies separately from formatting.

In a Git checkout, `npm ci` installs Husky's pre-commit hook. The hook runs lint-staged with Prettier only on supported staged files, using the same exclusions. lint-staged temporarily hides unstaged edits in partially staged files and restores them after formatting; unrelated unstaged files are left alone. If restoration conflicts, resolve the reported conflict and review the index before retrying. The hook does not run the full application suite. GitHub Actions runs `format:check` once through `npm run check`, along with the existing checks.

Source ZIP installation skips hook setup because there is no Git metadata; CI skips local hook setup too. To reinstall hooks in an existing checkout, run `npm run prepare`. Formatting tools are development dependencies and add nothing to the production bundle.

## Fonts, samples and visual baselines

For an intentional font change, retain its authoritative version/source and license, update the static URL descriptors and distinct real weight mappings, then run:

```sh
npm run fonts:coverage
npm run proof:generate
npm run check
```

[`scripts/font-coverage.mjs`](../scripts/font-coverage.mjs), invoked by `npm run fonts:coverage`, reads every bundled font using pdfmake’s pinned font reader and regenerates `src/pdf/font-coverage.ts`. It records the intersection of supported glyph ranges and each font’s SHA-256 hash for production glyph validation and regression checks. Run it after intentional font changes; do not edit the generated character list by hand. Preserve the fail-with-correction behavior for unsupported displayed glyphs; hidden URL destinations are not font coverage checks. Tests verify real embedded font identities/weights as well as text, links and bounds.

`proof:generate` writes seven synthetic PDFs to ignored `output/pdf/`. Render the changed pages with Poppler (`pdftoppm -r 100 -png <pdf> <output-prefix>`) and inspect the [layout checklist](../proof/README.md). Compare page counts, extracted text/order/links, actual coordinates/fonts/colors and page images rather than metadata-sensitive PDF byte hashes. Inspect header/bullet transitions, dividers and wrapped metadata at normal PDF scale.

Keep [the frozen pre-refresh fixture/PDF](../proof/baseline/pre-refresh/README.md) unchanged. [The current typical baseline](../proof/baseline/typical.pdf) changes only for an intentional, reviewed visual change after inspecting every affected page. A refactor with equivalent output needs no baseline refresh. Never replace a baseline merely to make a check pass, and never use personal resumes in fixtures or artifacts.

## Isolation and limits

Before dependency installation, cache removal, server restart or reload, copy any unsaved draft somewhere safe and stop only Applicable's own process. Pasted resume input exists only in the current browser page; HMR may also reset it. Do not run `npm ci` or clear `node_modules/.vite` under a live server. Verify clean installation in a separate source directory, and give temporary development tests their own cache/server with cleanup. [Cache recovery](development.md) explains the stale-dependency 504 and forced restart.

The narrow [pdfmake adapter](../src/pdf/pdfmake-adapter.ts) owns runtime validation of the pinned engine's private page/position metadata. C5's fit guard performs one additional layout pass over independently cloned keep-groups using pdfmake **0.2.20 internal `_pdfMakePages` and `positions` metadata**. It requires a target's first line to fit with its heading/preceding details on a fresh page; later bullet lines may continue. Missing measurement metadata blocks export. The pass can repeat shared headers and measure a long first bullet in full, so very large input has extra CPU/memory cost. Engine upgrades require rechecking compatibility, large passing/failing boundaries, font errors, browser recovery and ordinary-layout equivalence. See [the guard's design and limits](pdf-template.md).

Font coverage is finite, PDFs are selectable/searchable but not tagged accessibility PDFs, and native preview depends on browser settings. No universal layout guarantee is made for arbitrary documents. A failed fit check returns a warning and no partial artifact; do not truncate, shrink, rewrite or add a parser character cap to bypass it.

## React interface lifecycle

`main.tsx` mounts function components under React `StrictMode`. Pasted text uses local state; contact/company metadata is never persisted. The entry module removes only the legacy contact-storage key once at startup without reading its values; the generation hook owns the synchronous busy guard, revision checks, successful-font cache and current object URL. Resume PDF Maker is selected on every page load; `App.tsx` keeps all three tool panels mounted and hides inactive panels. The compact brand/tagline header precedes a detached tablist on the page background, then a separate white workspace containing all three mounted panels. Only the active tool’s primary heading is visible. Switching views must not invalidate drafts, errors, pending generation or the current artifact. Header tabs use automatic activation with Left/Right, Home and End; only the selected tab is in the tab order. Resume Writer’s formatting action selects Resume PDF Maker, expands its existing chatbot help and focuses the summary. `ResumeForm.tsx` resizes the textarea when visible again and ignores resize events while hidden. Keep PDF/parsing/filename modules framework independent. Successful delivery uses the committed result link once per artifact, and manual downloads reuse that URL. Replacing output, editing, page departure and unmount release the old URL. Lifecycle tests mount/unmount the actual app through a test-only Vite entry; production code exposes no test globals.

Font errors can be retried on the same page. A failed PDF-engine module import can remain cached by the browser for that page: copy the draft somewhere safe, fix the local asset/server problem, reload Applicable and paste the draft again. The warning explains that recovery; repeated same-page engine imports are not claimed to recover. No resume persistence is added.
